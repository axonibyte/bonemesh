# Known-defect registry

Every defect found by review or testing gets a row here, from discovery through
fix through gate verification. This registry serves double duty:

1. The fix list for hardening work.
2. The **validation-gate corpus** (testing-methodology): once the harness that
   should catch a defect exists, the defect is reverted on a scratch branch and
   the harness must rediscover it before its "gate" box is checked. A suite
   that cannot rediscover a known bug is a suite whose value is unmeasured.

Status: **open** → **fixed** (commit noted) → **gated** (rediscovery verified).

Until 3.3.0 no row had ever reached **gated**, although several said "gated by ..."
inside their prose -- the three-state machine was described and never used.
Rediscovery is verified two ways and both count: reverting the defect on a scratch
branch and watching a tier rediscover it, or, for a defect inside one
implementation, injecting it back as a mutation and watching the named test fail.
Those are the same idea at two scales. A row is promoted only when its own prose
records that this was actually done.

| D10 | Every Rust test that starts a real node pinned an absolute `const NOW: i64 = 1_788_600_000` and issued its certificates for `NOW-100 .. NOW+100_000` (~27 h). | D11 | `protocol.md` §2/§4 said an application payload larger than a transport frame is **chunked by the origin** (`chunk: {i, n}`) and pointed at §6 for how — and §6 never mentioned chunking at all. What shipped instead was an invented encoding in two ports: Java's `Chunker` and Elixir's `Message.split/5`, both base64-ing the payload and slicing it into `{"seg": ...}` at 32000 characters, with no spec text, no corpus vector and no bounds. The other five read `chunk.i` solely for the dedup key and then delivered `payload` straight to the application, so a Java or Elixir segment arrived as N separate `{"seg": "..."}` objects presented as whole messages — **silent corruption**, not the clean framing failure first recorded here. | all seven node and message layers | spec ↔ implementation divergence | **gated** (3.3.0): §6.1 now specifies splitting: 24000-byte UTF-8 segments cut on character boundaries, a top-level `seg` mutually exclusive with `payload`, the (`mid`, chunk index) dedup key, and four §0 bounds enforced before allocation. Implemented and mutation-checked in all seven. Gated three ways: `spec/corpus/chunk.json` pins the cut positions cross-language (nothing else could see that all seven cut in the *same* places), the 49-cell matrix now sends 96 KB in every cell with a two-marker oracle that separates reassembled from fragment from undelivered, and `messages.json` gained 15 chunk cases. Two corrections to this row's own history: it named Elixir among the non-chunking ports when Elixir implements both halves, and it generalised "measured on JS and Python" to all six. |
| D12 | Tier 8's first wait allowed 15s for routes to converge *and* the first delivery to land. That window also has to absorb cold process startup for up to four different runtimes (a cold `mix run` or JVM can eat most of it on its own), so under load — immediately after tier 7 drives seven implementations through a fuzz battery — the tier failed with "topology never converged" and then passed on a rerun seconds later. A gate that is re-run until green is not a gate. | `interop/tier8.sh` | test (flaky) | **gated**: the startup window is 30s and the node lifetime 90s, leaving 56s of waits inside a 90s lifetime. The oracles are untouched — delivery must still happen before any fault is injected — so this is patience, not a weakened assertion. Verified by injecting a real convergence break (a relay that advertises nothing): the tier still fails, naming both oracles, and passes again when restored. |
| D13 | `specsrc` (methodology tier 3) matched its skip patterns -- `vendor/`, `node_modules/`, `target/`, `build/`, `_build/`, `__pycache__` -- against each file's **absolute** path. Any ancestor directory sharing one of those names therefore excluded the entire tree. Bitbucket Pipelines clones into `/opt/atlassian/pipelines/agent/build`, so `"/build/"` matched every file in the repository and tier 3 found no implementation source at all. Invisible locally (`/home/cal/bonemesh/bonemesh`) and in every reaper tenant (`/reaper/work`, `/tank/work/...`), because none of those paths contain such a component. | `spec/conformance/cmd/specsrc/main.go` | implementation (environment-dependent) | **gated**: exclusions are matched against the path relative to the repository root. Reproduced before and after against a tree staged at `.../agent/build`. |
| D14 | The reassembler sized its segment buffer on the peer's `chunk.n` **before** validating it, so one frame could make a destination allocate on a number an unauthenticated-at-that-layer peer chose. Measured against the shipped jar at `-Xmx64m`: `n = 2000000000` raised `OutOfMemoryError` from a single frame. This is defect D7 (unbounded reads) reintroduced by the feature that was meant to close it — the frame cap bounds one read, and chunking existed precisely to lift that bound off application data, so it had to carry its own. | `java/.../message/Reassembler.java`, and by construction the Elixir accumulator, which had no bound of any kind | implementation | **gated** (3.3.0): bounds are checked before any allocation, and §0 pins four of them — segment size, chunk count, a shared byte budget across all in-flight messages, and an in-flight count. The last two are not redundant: a byte budget alone is satisfied by a flood of distinct `mid`s each carrying an empty segment. Gated by mutation in all seven (removing the ceiling reproduces the OOM), and the tests assert both that the offer is refused *and* that refusing it released what it claimed, because a reassembler that rejects a segment and keeps its partial forever is still a leak. |
| D15 | Java read `inner.getJSONObject("chunk").getInt("i")` unguarded on the data path, so a `chunk` that was not an object threw out of the read loop and killed the session; and separately, `optJSONObject` cannot tell an absent `chunk` from an unparseable one, so a message with a garbage `chunk` and a valid `payload` was **delivered** where Go, Rust and JS refused it. | `java/.../v3/Node.java`, `java/.../message/Reassembler.java` | implementation (divergence) | **gated** (3.3.0): the accessor degrades to the unsplit dedup key instead of throwing, and `has("chunk")` separates absent from unparseable. The distinguishing input — a garbage chunk on a message that *does* carry a payload — had no test in any port, which is how the divergence survived; it now has one in all seven. Corpus case `data-chunk-not-an-object` pins the verdict. |
| D16 | Every compiled interop helper was guarded by `[ -x "$bin" ] \|\| build`, which rebuilds only when the binary is **absent**. Editing a source and re-running a tier therefore exercised the previous build, and a check that reports PASS for code that is not the code under test is worse than no check. Not hypothetical: the 3.3.0 splitting work was invisible to the interop matrix until this was found, because `interop_node` predated it — the matrix reported five failing rows for a defect already fixed, and Go's rows failed for a reason that had never existed. | `interop/drivers/{go,rust}.sh`, `interop/tier{5,6,7,8,9,10}.sh`, `interop/run-matrix.sh` | test infrastructure | fixed (3.3.0): new `interop/ensure-bin.sh` compares binary mtime against its source roots, the same fix `ensure-jar.sh` already applied to the Java jar and for the same reason. Sibling check scripts using `go run` / `cargo run` were already immune and are left alone. |
| D17 | PHP reported a **partial socket write as success**. Its sockets are non-blocking, where `fwrite` writes only what fits in the kernel buffer and returns that count, and the test was `@fwrite(...) !== false` — true for a short write. The peer received a truncated line, never saw its terminating newline, and buffered until the frame cap closed the session. It could not happen while every message in the fleet was a sub-100-byte probe, and it was always latent for the handshake, where `security.md` notes a bmx2 with ML-DSA certificates runs near 20 KB. | `php/src/Node.php` | implementation | **gated** (3.3.0): a `writeAll` helper loops until every byte is out, waiting on `stream_select` rather than spinning when the socket would block, bounded so a peer that stops reading cannot wedge it. Every frame write goes through it, including the three handshake writes. PHP is the only port affected — Go's `conn.Write`, Rust's `write_all`, Java's `OutputStream.write`, Elixir's `:gen_tcp.send` and the buffered writers in JS and Python all deliver the whole buffer or fail. Found by the 96 KB matrix payload, which is the gate D11's fix added. |
| D18 | Java shipped its entire v2 implementation -- 23 files under `com.axonibyte.bonemesh`, including the `CryptoEngine` that *is* defect D8 -- alongside the v3 port, and the jar's `Main-Class` named its v2 entry point. No v3 class referenced any of it. The registry meanwhile described D8 as superseded and "gone". | `java/src/**` (non-`v3` packages), `java/build.gradle` | surface the protocol does not denote | fixed (3.3.0): deleted. Six v2 test classes went with it, and that is the only deletion of tests in this release -- the stated reason is narrow and exact, the code under test was removed, not the test. `Main-Class` is gone rather than repointed: nothing ever used it (every caller invokes a class by name on the classpath) and the artifact is a library that `doDeploy` publishes. The deletion also exposed `commons-cli` as a v2-only dependency with no remaining reference, so it is gone too -- an unused dependency is licence and supply-chain surface for nothing. |
| D19 | A reaper run whose SSH control channel drops mid-chain is reported as a SUCCESS. Observed on the root interop tenant: the channel died partway through tier 9, reaper printed "results are not coming back" and could not rsync `out/`, and `reaper test` still exited **0** -- while `tier10.sh` was demonstrably still executing on the guest (`pgrep` confirmed it, and the guest-side log was still growing). Any battery that trusts that exit code records a PASS for a run that neither finished nor returned a result. The guest was fine throughout: no OOM, no reboot, 6 GiB free, iptables clean, 26 minutes of uptime. | the pre-push battery harness, not the repository | test infrastructure (environment) | **mitigated, not fixed**, and deliberately recorded rather than worked around. The cause sits in reaper and/or a long-lived SSH session, outside this repository. What is fixed is the harness that believed it: the battery now takes the interop verdict from evidence -- the retrieved guest log must contain the final tier's own pass line -- and treats "results are not coming back" as disqualifying whatever the exit code says. The re-run retrieved results cleanly and the full chain passed, tier 6's netem work and all 24 of tier 9's seeded actions included. Worth the row because it is the same defect shape as D16 one layer up: a gate reporting PASS for code it did not actually exercise. |
