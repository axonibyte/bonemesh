# Known-defect registry

Every defect found by review or testing gets a row here, from discovery through
fix through gate verification. This registry serves double duty:

1. The fix list for hardening work.
2. The **validation-gate corpus** (testing-methodology): once the harness that
   should catch a defect exists, the defect is reverted on a scratch branch and
   the harness must rediscover it before its "gate" box is checked. A suite
   that cannot rediscover a known bug is a suite whose value is unmeasured.

Status: **open** → **fixed** (commit noted) → **gated** (rediscovery verified).

| D10 | Every Rust test that starts a real node pinned an absolute `const NOW: i64 = 1_788_600_000` and issued its certificates for `NOW-100 .. NOW+100_000` (~27 h). Gated by mutation check: swapping the responder's role→direction keylog mapping makes the revived keylog test fail, so the restored tests demonstrably have teeth. |

| D11 | `protocol.md` §2/§4 says an application payload larger than a transport frame is **chunked by the origin** (`chunk: {i, n}`), but only Java implements it (`Chunker.java`/`Reassembler.java`). Go, Rust, JS, PHP, Elixir and Python read `chunk.i` solely to build the dedup key and never split on send, so an oversized payload is written as one over-cap frame: the peer rejects it at the framing layer and closes the session, nothing is delivered, and `send()` has already returned **true** to the caller. Measured on JS and Python (both deliver 0 for a 100 KB payload where a small control delivers 1), so it is a property of all six non-Java ports and not of any one of them. | `go/`, `rust/`, `js/`, `php/`, `elixir/`, `python/` node layers | spec ↔ implementation divergence | **open**. Not fixed here: chunking in one port alone would not help, because only Java could reassemble it — a payload chunked by Python still fails to every other non-Java peer. The fix is either chunk+reassemble across all six or narrow the spec to make chunking optional and have `send()` refuse an oversized payload; that is a deliberate protocol decision, not a porting detail. Documented in `architecture.md` §7 so it is a known boundary rather than a surprise. |
| D12 | Tier 8's first wait allowed 15s for routes to converge *and* the first delivery to land. That window also has to absorb cold process startup for up to four different runtimes (a cold `mix run` or JVM can eat most of it on its own), so under load — immediately after tier 7 drives seven implementations through a fuzz battery — the tier failed with "topology never converged" and then passed on a rerun seconds later. A gate that is re-run until green is not a gate. | `interop/tier8.sh` | test (flaky) | fixed: the startup window is 30s and the node lifetime 90s, leaving 56s of waits inside a 90s lifetime. The oracles are untouched — delivery must still happen before any fault is injected — so this is patience, not a weakened assertion. Verified by injecting a real convergence break (a relay that advertises nothing): the tier still fails, naming both oracles, and passes again when restored. |
| D13 | `specsrc` (methodology tier 3) matched its skip patterns -- `vendor/`, `node_modules/`, `target/`, `build/`, `_build/`, `__pycache__` -- against each file's **absolute** path. Any ancestor directory sharing one of those names therefore excluded the entire tree. Bitbucket Pipelines clones into `/opt/atlassian/pipelines/agent/build`, so `"/build/"` matched every file in the repository and tier 3 found no implementation source at all. Invisible locally (`/home/cal/bonemesh/bonemesh`) and in every reaper tenant (`/reaper/work`, `/tank/work/...`), because none of those paths contain such a component. | `spec/conformance/cmd/specsrc/main.go` | implementation (environment-dependent) | fixed: exclusions are matched against the path relative to the repository root. It failed loudly rather than passing vacuously only because of the "no implementation source found at all" guard, which is the case for writing such guards. Two self-test cases added (`interop/check-spec.sh --self-test`): a root nested under a directory named `build/` must still be searched, and a vendored file must still be unable to satisfy a constant the real source lacks — so neither the bug nor an over-broad fix for it can return quietly. Reproduced before and after against a tree staged at `.../agent/build`. |
