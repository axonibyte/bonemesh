# Decisions

Lightweight decision registry. One entry per settled decision; newest at the
bottom. Revisiting a decision gets a new entry that names the one it replaces.

| # | Date | Decision | Rationale |
|---|---|---|---|
| 1 | 2026-09-04 | The protocol specification is the product; implementations conform to it. No port begins before the v3 spec exists. | Six implementations of one ambiguous codebase would be six projects; a spec plus conformance vectors makes them one. |
| 2 | 2026-09-04 | Super-repo layout: `docs/`, `spec/`, `interop/`, one folder per language, no `bonemesh-` folder prefix. | Spec, corpora, and implementations move in lockstep; cross-repo interop testing is miserable. Repo name already carries the brand. |
| 3 | 2026-09-04 | Wire format is JSON everywhere; no binary serialization. | Readability of the objects in flight is a design value of the project. |
| 4 | 2026-09-04 | v3 security: Noise-framework-style authenticated handshake, hybrid X25519 + ML-KEM (FIPS 203), ML-DSA (FIPS 204) node identities. NIST PQC where possible. | Owner requirement for NIST PQC; hybrid rather than PQ-only so a flaw in young ML-KEM implementations doesn't drop the mesh below classical security. Supersedes the dev-branch Kyber prototype (round-3 draft, unauthenticated key distribution). |
| 5 | 2026-09-04 | "Readable in flight" under encryption means: plain JSON at the protocol layer, plus a spec'd session-key logging hook and a bundled inspector tool for development. | Keeps the readability guarantee without a plaintext production mode. |
| 6 | 2026-09-04 | PHP is a full routing node, same peer status as the other implementations. | Owner call; no special-casing in the spec. |
| 7 | 2026-09-04 | Testing follows reaper's testing-methodology.md: per-language reaper tenants own tiers 1-4; a root interop tenant owns tiers 5-9, written once, language-agnostic. | Verified reaper resolves the synced tree from the manifest's directory, so subdirectory tenants need no reaper changes. Black-box harnesses over TCP don't care about implementation language. |
| 8 | 2026-09-04 | Baseline is the former `dev` branch (d807d83); `main` fast-forwarded to it. | dev was strictly ahead (Java 17, NPE fix #3, crypto prototype). The prototype is replaced, not extended (see #4). |
| 9 | 2026-09-04 | Port order after Java: Elixir, Rust, Go, JS, PHP. | Elixir is the most different runtime and stress-tests the spec earliest; PHP is the hardest port and benefits most from a mature spec and conformance suite. |
| 10 | 2026-09-04 | Java targets the latest LTS (25), via Gradle toolchains; pipeline image is eclipse-temurin:25-jdk. | Owner call. Library consumers need Java 25+ from the next release. |
| 11 | 2026-09-04 | v3 membership: a per-mesh root ML-DSA keypair signs each node's identity into a membership certificate; a node proves membership by presenting a cert that verifies against the pinned root key. | Owner call among allowlist / root-signed / TOFU. Strongest of the three; CA-like trust without X.509; supports expiry and revocation. Resolves PLAN §8.1. |
| 12 | 2026-09-04 | The conformance runner and interop harnesses are written in Go. | Owner call (Go vs Rust). ML-KEM/X25519 in the stdlib, single static binaries, easy in reaper guests. Resolves PLAN §8.3. |
| 13 | 2026-09-04 | v3 relay trust is hop-by-hop: neighbors hold authenticated sessions and a relaying member decrypts and re-encrypts to the next hop. Mesh members trust each other; end-to-end payload protection against untrusted relays is deferred (format reserves room). | Follows from the members-trust-each-other model; keeps v3 tractable across six languages. Resolves PLAN §8.5 for v3. |
| 14 | 2026-09-06 | The `bonemesh-ca` provisioning tool and the `bonemesh-inspect` key-log decryptor are Go commands under `go/cmd/`; the earlier Java `BoneMeshCA` CLI is retired (Java's certificate *library* stays — the node needs it). | One canonical operator toolset in a compiled language with a minimal footprint. The Go module already vendors CIRCL (ML-DSA-65/87) and reuses the corpus-verified `cert`/`canon`/`crypto` packages, so provisioning needs no JDK and no logic is duplicated. Extends #12 (Go for conformance/tooling). Go-issued and Java-issued certs verify interchangeably (proven by round-trip). |
| 15 | 2026-09-06 | The session-lifecycle behaviors 3.0.0 specified-but-deferred (simultaneous-dial tiebreak, retry/backoff, probe-timeout death, idle teardown, periodic rekey, ack/NAK emission) are all delivered in 3.1.0 across every implementation, each governed by a `BONEMESH_*` env var read once at node start with a tier-safe default (probe 15 s, idle disabled, retry 500 ms→30 s, rekey 1 h / 2¹⁶ frames). | Defaults chosen so no existing interop tier needs env changes; env-tunability lets operators and the feature-behavior tier exercise the behaviors without recompiling. Cures the deferred-feature deficiencies by implementation, not omission. |
| 16 | 2026-09-06 | The key-log line format is pinned as `BMX3_{I2R,R2I}_TRAFFIC_<epoch> <hex transcript-hash> <hex 32-byte key>` (epoch 0 at handshake, +1 per rekey; `#` comments and unknown labels ignored). | A frozen, corpus-pinned format (`spec/corpus/keylog.json`) so any implementation's emitter feeds `bonemesh-inspect` regardless of language; modeled on `SSLKEYLOGFILE`. Realizes the readability hook promised in #5. |
| 17 | 2026-09-06 | Periodic rekey triggers on frame count OR age (whichever first), initiator-only, tunneling a fresh BMX exchange inside four `rekey` transport frames with an exact per-direction swap boundary; a peer that ignores rekey keeps the old keys and the initiator re-arms after `BONEMESH_REKEY_TIMEOUT_MS` (safe degrade, no capability negotiation). | Count-or-time bounds both data volume and wall-clock exposure per key; tunneling inside transport needs no new cleartext message class; safe-degrade avoids a version-negotiation handshake for a peer that predates the feature. |
| 18 | 2026-09-06 | The feature-behavior interop tier (tier 10) joins the standard root battery; the long-horizon soak (tier 11) does not — it runs only behind an explicit `BONEMESH_LONG_SOAK=1`/`--long-soak` gate. Only the Go interop node implements the `--capture` driver flag. | Tier 10 is bounded and deterministic enough for every CI run; a multi-hour soak is not, so it is opt-in and its bundle reviewed by hand. One capturing implementation suffices to exercise every language's key-log emitter cross-language (tier 10 keylog round-trip), so the flag isn't duplicated five more times. |

| 19 | 2026-09-12 | Python is the seventh implementation, built on `asyncio`, with `cryptography` (pyca) as its single runtime dependency. | CPython's stdlib has no ML-KEM or ML-DSA, so unlike the JS and Elixir ports this one cannot be dependency-free; `cryptography` over OpenSSL 3.5 gives the whole primitive set the other ports get from Node or OTP. asyncio because a single event loop matches the JS port's decomposition one-to-one, so there is no shared-state race to guard. |
| 20 | 2026-09-12 | Third-party dependencies are licence-gated in the build, not reviewed by hand. | BoneMesh is Apache-2.0, which is one-way incompatible with GPL-2.0, so one copyleft transitive dependency is disqualifying. `python/tools/check_licenses.py` fails the build on anything outside a permissive allowlist and refuses to pass if it cannot see the dependency it audits — the first version of it shipped as a PEP 723 script, inspected an isolated empty environment, and reported success. |
| 21 | 2026-09-12 | Methodology tier 3 (source-as-data) is a single shared tool over every implementation, not a per-language obligation. | `PLAN.md` §5 and `architecture.md` §5 had listed it per-language since M3 and no implementation ever had one. "Did this spec edit land in the code, and does the code read tunables the spec never documents?" is the same question in every language, and answering it needs the whole repository — so one Go tool (`spec/conformance/cmd/specsrc`, consistent with #12) driven from `interop/`. |
| 22 | 2026-09-12 | The byte-exact corpus checks are gated — in the root reaper tenant and in CI — and a missing check fails rather than skips. | They are the only oracles that compare an implementation against the shared corpus byte-for-byte (the in-tenant suites mirror the vectors, because a tenant syncs one subtree and cannot see `spec/corpus`), and nothing invoked them: the claim was unrun. Treating an absent script as a skip would let the grid rot quietly, so `run-corpus-checks.sh` fails on a hole. |
| 23 | 2026-09-12 | **Reference implementations shall do nothing more than what the protocol expressly denotes, outside standard language-specific plumbing.** Surface that is not in the spec is either specified or removed; a divergence is resolved in one direction or the other, never left standing. The carve-out is named rather than left to judgement: it covers what a language forces on a port and nothing else — PHP's `serve(seconds, tick)` qualifies because PHP has no threads and the caller must pump the loop; Go's `Config.CapturePath` qualifies under #14/#18; a public `broadcast()`, a `label()` accessor or an exported test seam does not. | The registry had been recording divergences as defects one at a time while the spec quietly drifted from the seven things implementing it. What forced the rule: `0110dad` removed a `broadcast()` that only the Python port had, and it had survived the entire 8x7 corpus grid run twice, `specsrc`, the 49-cell matrix and tiers 5-10 — it was caught by a human diffing two implementations method-for-method, because nothing in the repository asks "does this port do more than it should?". The rule is only worth having if it is gated, so it arrives with the code->spec checks of #24. |
| 24 | 2026-09-12 | The conformance gates run in **both** directions: spec->code (does the pinned thing appear?) and code->spec (does the implementation do something the spec never denoted?). | Before 3.3.0 exactly one check ran code->spec — `specsrc` check B, on `BONEMESH_*` tunable names — and it is the only reason an undocumented knob was ever impossible to land. Every other axis was one-directional, so a spec'd type with no corpus vector, an emitted field the spec never named, and an extra public method were all invisible by construction. #23 cannot be enforced by reading the requirement again; it needs the missing direction. |
| 25 | 2026-09-12 | Chunk segments are **UTF-8 text slices carried in a JSON string**, not base64, bounded by pinned wire constants. | Chunking shipped in Java and Elixir as `{"seg": "<base64>"}` with a 32000-char segment and no spec text, no corpus vector and no bounds. Base64 is not necessary — a JSON string carries UTF-8 directly, and a payload's serialization is JSON text, which RFC 8259 forbids from holding an unescaped control character, so re-escaping costs only one byte per `"` or `\`: measured 1.00x-1.18x on realistic payloads against base64's fixed 1.333x, worst case bounded at 2x. The decider is #3 — an opaque base64 blob is exactly the binary-serialization opacity that decision rejects, one layer up, and it defeated #5's inspector. A 24000-byte segment carries the same payload per frame as the old 32000 base64 chars, so the change costs no extra frames. |
| 26 | 2026-09-12 | Where the spec and all seven implementations disagreed, the **spec was corrected** — for the single `auth` member and for the handshake transcript. | Judged on design merit, not on what shipped. `security.md` §4's separate `cert` and `sig` members leave three orderings unstated (whether `ENC(cert)`'s ciphertext is absorbed into `h` before `ENC(sig)`, whether the signature pre-image includes that absorption, whether the two seals share a nonce counter) and `ENC` uses `h` as associated data, so each changes the derived keys: two implementations could both follow §4 literally and fail to interoperate. The single `auth` seal has none of those degrees of freedom. §5's "raw wire bytes are absorbed in order" contradicts §4's own statement that the handshake's shape *is* Noise `XX`: Noise `MixHash`es each token as it is written after a `MixHash(prologue)`, which is what all seven do with `mesh` as that prologue. §5's rule is also circular — message 2's bytes cannot be absorbed before sealing `auth`, which needs `h` — and would leave `e_r` and `ct` outside the responder's signature pre-image. Neither correction changes the wire, so `v` stays 3. |
| 27 | 2026-09-12 | The message schemas are a **sender conformance surface**, not a receiver gate. | `message.validate()` was called from no node's wire path in any of the seven — only from the corpus-check binaries — so the `messages` family validated a side-car with no effect on live behaviour, and `python/tests/test_hostile_inner.py` pins node and validator *deliberately* disagreeing. Making readers strict is not available: §8 mandates tolerating unknown inner types and new optional fields. So the schemas define what a conforming emitter must produce, and #24's emitted-message check supplies the direction that makes the family mean something. |

| 28 | 2026-09-13 | A transport or framing fault **closes the session and says why** (`bye{reason:"protocol-error"}`) in all seven; an inner `type` the receiver does not recognize does neither. The `rekey-failed` close reason is **removed** from the spec rather than implemented. | Two of the three reasons §8 called defined were unreachable, and the registry was about to gain a row for each. `protocol-error` is now reachable: the faults it names (oversize frame, not one JSON object, AEAD tag failure, `seq` out of order) already ended the connection in every port, so nothing about the close changes — the peer learns the cause instead of inferring it from a dropped socket, and the sending half is unaffected by a receive-side fault because keys and counters are per-direction. `rekey-failed` cannot be implemented without contradicting `security.md` §6, which specifies that a rekey the peer ignores degrades safely and keeps the old keys so an older peer keeps working; a close would convert "the peer predates this feature" into a dropped session, and #17 chose that degrade deliberately over capability negotiation. Forward secrecy does not depend on it either (§6 says so explicitly). The reason the spec loses the name rather than keeping an aspiration: under #23 a defined-but-unemitted reason is exactly the drift the rule exists to stop. Implementing it also required settling what a fault *does* — four ports dropped the frame and kept the link, three closed (D20) — and §4's strict-in-order rule already demanded the teardown. |


| 29 | 2026-09-13 | The public API surface is pinned as a **per-language name table** (`spec/corpus/api.json`) listing each capability's name in each of the seven, with "reachable but not API" read from each language's own marker. Parity is checked on the set of callable names only — not on signatures, and not on behaviour. | #23 could not be enforced against the API because nothing could say what the API *was*. Two things had to be decided to make it checkable. First, names: idiom genuinely differs (`SendM`, `sendMid`, `send_mid`; `routes` vs `route_table`; `stop` vs `kill`), so a check that inferred names would be wrong on its first run, and a check that forced one spelling would make six ports unidiomatic to satisfy a gate. The table is duplication, deliberately — it is the second, independent statement the implementations are compared against. Second, seams: every port has a reachable-but-not-API method, and each language marks it differently (`#[doc(hidden)]`, `@doc false`, package-private, an `@internal` docblock, a leading underscore, unexported). Honouring those markers is the feature: a naive sweep reports Rust's `send_with_ttl` and `rekey_epoch`, which carry an explicit "Not API" rationale citing #23, and a gate that cries wolf is a gate that gets switched off. Signatures are excluded on the same reasoning that kept the emitted-field check to a field allowlist — a cross-language signature model is not maintainable, and the matrix and tiers 5-12 already answer behaviour. |
